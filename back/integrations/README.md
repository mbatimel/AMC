# Интеграция с 1С

Цель: воркер, раз в день забирающий из 1С (УТ 10.3) номенклатуру, цены и остатки, и заполняющий ими таблицы `products`.

## Инфраструктура 1С (по состоянию на 2026-08-25)

- Сервер: `PVISERVER`, кластер 1С:Предприятие 8.3, локальный кластер.
- Базы в кластере: `BUH`, `UT`, `ZUP`, `UT081225`, `BUH081225`, `BUH290426`, `BUH_Proba`, `ZUP_Proba`, `UNF`.
- Нужная база — **`UT`** (Управление торговлей, редакция 10.3). Остальные — бухгалтерия/зарплата/тестовые копии, не относятся к товарам.
- СУБД: **PostgreSQL** (форк "PostgreSQL для 1С").
- Совместимость конфигурации: `Version8_3_27` — платформа новая, стандартный интерфейс **OData поддерживается** (нужна версия 8.3.5+).
- На сервере **не установлен веб-сервер** (IIS) — `http://localhost/` не отвечает. Без веб-сервера ни OData, ни HTTP-сервисы не опубликовать.
- Готовый **Web-сервис "Exchange"** (SOAP) уже есть в конфигурации: методы `Upload`/`Download`/`UploadData`/`DownloadData`/`GetIBData`/`GetIBParameters` и т.д. — это стандартный сервис обмена по плану обмена (внутренний XML-формат 1С, используется для интеграции с сайтом/1С-Битрикс). Технически рабочий канал, но формат нестандартный и требует настройки узла обмена — не первый выбор.
- Узел "HTTP-сервисы" в дереве конфигурации есть, но пуст — кастомных HTTP-сервисов под нашу задачу нет.

### Прямое подключение к БД

Технически возможно (СУБД — Postgres), но **не рекомендуется**:
- Таблицы 1С называются автогенерируемыми именами (`_Reference123`, `_AccumRg456` и т.д.), маппинг на бизнес-объекты не документирован и меняется при обновлении конфигурации.
- Ссылки — бинарные UUID, суммы — в специфичном NUMERIC формате.
- Риск блокировок/нагрузки на прод при прямых SELECT.

## Рекомендуемый путь

1. Установить роль **IIS** на сервере `PVISERVER` (сисадминская задача, не требует 1С-программиста — Диспетчер серверов → Добавить роли → Веб-сервер IIS).
2. В Конфигураторе базы `UT`: **Администрирование → Публикация на веб-сервере**, включить галку **"Стандартный интерфейс OData"**.
3. Создать отдельного технического пользователя 1С с правами только на чтение нужных справочников/регистров.
4. Воркер (Go, `back/integrations`) раз в день ходит по OData (`GET /UT/odata/standard.odata/...`) с Basic Auth, тянет изменения, пишет в `products`.

Если OData в итоге недоступен — запасной вариант: попросить 1С-разработчика написать кастомный HTTP-сервис с одним-двумя методами (отдаёт JSON), либо настроить регламентную выгрузку в CSV/JSON в шаренную папку.

## Соответствие объектов 1С (УТ 10.3) и модели `products`

Основано на выгруженном `Configuration.xml` (манифест конфигурации, список объектов верхнего уровня — без детальных реквизитов, т.к. выгружены файлами были только `AccumulationRegisters`).

| Поле в `products` (`back/products/pkg/models/products.go`) | Объект 1С | Комментарий |
|---|---|---|
| `Product` (карточка) | `Catalog.Номенклатура` | справочник товаров |
| `Product.SKU` | реквизит `Номенклатуры` (Артикул/Код) | точное имя реквизита не подтверждено — манифест не даёт деталей объекта |
| `Product.Name` | реквизит `Наименование` | стандартный реквизит |
| `Product.CategoryID/CategoryName` | `Catalog.НоменклатурныеГруппы` | иерархический справочник групп товаров |
| `Product.BasePrice/ClientPrice` | `InformationRegister.ЦеныНоменклатуры` | периодический регистр; измерение `ТипЦены` → `Catalog.ТипыЦенНоменклатуры`. Какой тип цены = базовая/клиентская — уточнить у разработчика 1С |
| `Product.DiscountPercent` | `InformationRegister.СкидкиНаценкиНоменклатуры` (или `СкидкиНаценкиПоЦеновымГруппам`) | |
| `Product.StockQty` / `ProductStock.StockQty` | `AccumulationRegister.ТоварыНаСкладах` | измерения `Номенклатура`+`Склад`, ресурс `Количество` |
| `ProductStock.Warehouse` | `Catalog.Склады` | |
| `Promotion` | `InformationRegister.ВремяДействияСкидок` + `СкидкиНаценкиНоменклатуры` | старт/энд периода + процент |
| штрихкоды (доп.) | `Catalog.ШтрихкодыУпаковокТоваров` | если понадобятся |
| единицы измерения (доп.) | `Catalog.ЕдиницыИзмерения` | |

### Не найдено в манифесте (требует уточнения у 1С-разработчика)

- `Product.BrandID/BrandName` — нет отдельного справочника "Бренды/Производители". Вероятно реализовано через `Catalog.ЗначенияСвойствОбъектов` + `Catalog.КатегорииОбъектов` (механизм доп. реквизитов и сведений УТ 10.3), либо кастомный реквизит прямо в `Номенклатуре`.
- `Product.GOST`, `Product.Material`, `Product.Size` — та же история: либо доп.свойства, либо кастомные реквизиты `Номенклатуры`.
- `Product.Images` — в УТ 10.3 нет штатного механизма картинок товара. Вероятно, ведётся не в 1С — уточнить, откуда сейчас берутся изображения.

Чтобы закрыть пробелы: развернуть `Справочники → Номенклатура → Реквизиты` прямо в Конфигураторе (доступ уже есть) и свериться со списком полей, либо спросить у 1С-разработчика напрямую.

## Черновик запроса 1С-разработчику

```
Нужен доступ к данным УТ 10.3 для интеграции с сайтом/внешним сервисом — раз в день забираем
номенклатуру, цены и остатки.

Что нужно получать:
- Номенклатура: артикул/код, наименование, категория/группа, бренд, ГОСТ, единица измерения,
  характеристики (если используются)
- Цены: по типам цен из ТипыЦенНоменклатуры (какие типы актуальны — розничная/оптовая/
  клиентская, уточните какой брать)
- Остатки: по складам или суммарно — как удобнее вам

Как технически организовать доступ (на ваше усмотрение, любой вариант устроит):
1. Опубликовать базу на веб-сервере (IIS/Apache) с включённым стандартным интерфейсом OData —
   самый быстрый вариант, платформа (8.3.27) это поддерживает
2. Либо HTTP-сервис с одним-двумя методами (GET список номенклатуры с ценами/остатками) —
   если так удобнее вам

Что нужно от вас:
- Отдельный технический пользователь с правами только на чтение нужных справочников/регистров
  (без полного доступа)
- URL для подключения (если воркер будет ходить снаружи — доступ по интернету с ограничением
  по IP, или через VPN — как у вас принято)
- Название регистра/регистров с ценами и остатками, если отличается от найденного нами
  (ЦеныНоменклатуры, ТоварыНаСкладах)
- Где физически хранятся Бренд/ГОСТ/Материал/Размер — не нашли отдельных справочников
- Есть ли поле даты изменения у объектов — для инкрементальной синхронизации (тянуть только
  изменённое, а не всю базу каждый раз)
```

## Статус

Воркер реализован (`back/integrations`, сервис `onec-sync` в `deploy/docker-compose.yml`).
Дизайн и объём v1 — `docs/superpowers/specs/2026-08-25-onec-sync-worker-design.md`.

Синкает раз в сутки (или после рестарта контейнера сразу): категории
(`Catalog.НоменклатурныеГруппы`), склады (`Catalog.Склады`), товары — артикул/наименование/
категория (`Catalog.Номенклатура`), цены (`InformationRegister.ЦеныНоменклатуры`), остатки по
складам (`AccumulationRegister.ТоварыНаСкладах`). Brand/GOST/Material/Size/Images/единицы
измерения/группы цен — вне объёма v1, см. спек.

Заблокировано на **публикации OData на сервере `PVISERVER`** (см. раздел "Рекомендуемый путь"
выше — IIS + галка "Стандартный интерфейс OData" в Конфигураторе, плюс технический
пользователь на чтение). Имена OData entity set'ов/полей в `internal/onec/models.go` —
best-effort по стандартному именованию 1С, не сверены с реальным сервером. После публикации:
1. Заполнить `ONEC_BASE_URL`/`ONEC_USER`/`ONEC_PASSWORD` в `deploy/.env`.
2. Прогнать воркер разово (`docker compose up onec-sync` или локально `go run ./cmd`
   из `back/integrations`) и свериться с логами (`sync_logs` в БД, либо просто вывод —
   воркер логирует каждый OData-ответ целиком).
3. Поправить константы `entitySet*` и JSON-теги DTO в `internal/onec/models.go`, если реальные
   имена отличаются от предположенных.
