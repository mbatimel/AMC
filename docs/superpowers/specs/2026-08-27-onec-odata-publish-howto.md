# Как опубликовать OData в 1С:УТ 10.3 для воркера `onec-sync`

Инструкция для тебя самого (не для внешнего 1С-разработчика) — как включить стандартный
интерфейс OData на сервере `PVISERVER`, база `UT`, и подключить к этому уже написанный воркер
`back/integrations`. Основано на разведке в `back/integrations/README.md` (платформа
`8.3.27`, OData поддерживается, IIS на момент разведки не стоял).

Технических деталей 1С-администрирования тут больше, чем в остальных наших доках — часть шагов
может отличаться в мелочах от твоей реальной установки (версия IIS, локализация). Общая
последовательность верна для 1С:Предприятие 8.3.

## 1. Веб-сервер (если ещё не установлен)

На `PVISERVER`, Диспетчер серверов → Добавить роли и компоненты → роль **"Веб-сервер (IIS)"**.
Достаточно базового набора; специфичных доп. модулей IIS не требуется — их подключит инсталлятор
платформы 1С на следующем шаге.

Проверить, что IIS реально поднялся: `http://localhost/` на самом сервере должен отдать
дефолтную страницу IIS.

## 2. Модуль расширения веб-сервера от 1С

Без этого IIS не умеет отдавать запросы к базе 1С. Обычно ставится вместе с платформой
1С:Предприятие, но иногда — отдельным компонентом:

- Запусти инсталлятор дистрибутива платформы 1С (тот же `.msi`/`setup.exe`, которым ставилась
  сама платформа на сервере).
- В списке компонентов найди **"Модули расширения веб-сервера"** (英: "Web server extension
  modules") — если не был отмечен при первой установке, доустанови сейчас.
- Это кладёт `wsisapi.dll` в каталог `bin` платформы (`C:\Program Files\1cv8\<версия>\bin\`) —
  именно его IIS дальше будет вызывать для обработки запросов к базе.

## 3. Публикация базы `UT` с OData

Два способа — любой рабочий:

### 3a. Через толстый клиент (проще, если у тебя есть доступ к Конфигуратору)

1. Открой базу `UT` в режиме **Конфигуратор**.
2. Меню **Администрирование → Публикация на веб-сервере...**
3. В диалоге:
   - **Веб-сервер:** IIS (если несколько сайтов — выбрать нужный, обычно "Default Web Site").
   - **Имя** (это будет частью URL, например `UT` → база доступна на `http://PVISERVER/UT/`).
   - Каталог публикации — оставить дефолтный, или указать свой (например
     `C:\inetpub\wwwroot\UT`).
   - **Отметить галку "Стандартный интерфейс OData"** — это ключевой чекбокс, без него OData не
     включится, даже если сама база опубликована.
   - Там же обычно можно выбрать конкретные объекты, доступные через OData (если список
     показан) — если есть такая возможность, разумно ограничить только нужными: `Номенклатура`,
     `НоменклатурныеГруппы`, `Склады`, `ЦеныНоменклатуры`, `ТоварыНаСкладах` (регистр остатков).
     Если галки по объектам нет — публикуется весь доступный (для техпользователя) набор,
     фактическое ограничение тогда только правами пользователя (шаг 4).
4. Подтвердить — 1С сама сгенерирует `default.vrd` и настроит IIS-приложение по указанному
   пути.

### 3b. Через `webinst.exe` (без толстого клиента, командная строка)

```
webinst.exe -publish -iis -connstr "Srvr=<адрес-кластера>;Ref=UT;" -wsdir UT -dir "C:\inetpub\wwwroot\UT" -confPath "C:\Program Files\1cv8\common\1cv8wsdef.xml"
```

Опция за включение OData в `webinst.exe` — обычно отдельного флага нет, OData включается через
редактирование сгенерированного `default.vrd` вручную: открыть файл, найти секцию
`<point name="odata" ... enable="false">` (или похожую), поставить `enable="true"`. Проще и
надёжнее — способ 3a через Конфигуратор, если доступ есть.

## 4. Технический пользователь для воркера

В Конфигураторе базы `UT`: **Администрирование → Пользователи** → создать нового.

- Логин/пароль произвольные — их же пропишем в `.env` воркера.
- Права — **только чтение** нужных объектов. Проще всего: создать отдельную **Роль** с правом
  "Чтение" на:
  - `Справочник.Номенклатура`
  - `Справочник.НоменклатурныеГруппы`
  - `Справочник.Склады`
  - `РегистрСведений.ЦеныНоменклатуры`
  - `РегистрНакопления.ТоварыНаСкладах`

  и назначить эту роль новому пользователю (без остальных стандартных ролей типа
  "Полные права").
- Не забыть поставить **"Аутентификация по протоколу HTTP"** (или "Аутентификация 1С:Предприятие"
  — то, что реально используется для OData Basic Auth) в свойствах пользователя, иначе логин по
  Basic Auth не пройдёт даже с верным паролем.

## 5. Проверка публикации (до запуска воркера)

С любой машины с доступом к серверу:

```bash
curl -u "<логин>:<пароль>" "http://PVISERVER/UT/odata/standard.odata/\$metadata"
```

Ожидаемо: XML с описанием всех доступных entity set'ов (длинный документ, `Content-Type:
application/xml`). Если 401 — не тот логин/пароль или не включена аутентификация у
пользователя. Если 404 — публикация не создалась или OData не включён (вернуться к шагу 3).

Дальше проверить конкретный entity set, который использует воркер:

```bash
curl -u "<логин>:<пароль>" "http://PVISERVER/UT/odata/standard.odata/Catalog_Номенклатура?\$format=json&\$top=1"
```

Если получаешь `{"value":[{...}]}` с одной записью товара — публикация работает. **Важно:**
запиши реальные имена полей в этом JSON (например `Ref_Key`, `Code`, `Description`,
`НоменклатурнаяГруппа_Key` — но реальные могут отличаться) — это понадобится на шаге 7.

Если имя entity set'а `Catalog_Номенклатура` даёт 404 — попробуй `\$metadata` (шаг выше) и
поищи там реальное имя (иногда отличается регистром или структурой, хотя для стандартных
справочников 1С обычно `Catalog_<ИмяСправочника>` без исключений).

## 6. Настроить и запустить воркер

В `deploy/.env` (не в `.env.example` — это реальный секретный файл):

```
ONEC_BASE_URL=http://PVISERVER/UT/odata/standard.odata
ONEC_USER=<логин техпользователя>
ONEC_PASSWORD=<пароль>
```

Прогнать воркер разово, чтобы увидеть реальный результат:

```bash
cd back/integrations
go run ./cmd
```

(или `docker compose up onec-sync` из `deploy/`, если тестируешь через полный стек). Воркер сам
логирует каждый OData-ответ целиком на уровне Debug — смотри вывод в консоли, либо таблицу
`sync_logs` в БД (`SELECT * FROM sync_logs ORDER BY created_at DESC LIMIT 50;`) — там же
`sync_jobs.status` покажет `success`/`partial`/`failed` по итогу прогона.

## 7. Сверить имена полей и поправить код, если разошлись

Имена entity set'ов и JSON-полей, которые сейчас зашиты в
`back/integrations/internal/onec/models.go`, — best-effort по стандартному именованию 1С OData,
**не сверены с реальным сервером**. Если шаг 5/6 показал другие реальные имена — поправить
константы там же:

```go
// back/integrations/internal/onec/client.go
const (
	entitySetCategories = "Catalog_НоменклатурныеГруппы"
	entitySetWarehouses = "Catalog_Склады"
	entitySetProducts   = "Catalog_Номенклатура"
	entitySetPrices     = "InformationRegister_ЦеныНоменклатуры"
	entitySetStock      = "AccumulationRegister_ТоварыНаСкладахBalance"
)
```

```go
// back/integrations/internal/onec/models.go — JSON-теги на полях DTO,
// например `RefKey string `json:"Ref_Key"``  — поправить строку в кавычках,
// если реальное поле называется иначе.
```

После правок — заново `go build ./... && go test ./...` в `back/integrations`, затем ещё раз
прогнать воркер (шаг 6) и свериться, что `sync_jobs.status = 'success'` и в таблицах
`products`/`categories`/`warehouses`/`product_prices`/`stock_balances` появились реальные
строки с `one_c_guid`.

## 8. Частые проблемы

- **401 на всех запросах, хотя логин/пароль верны** — проверь, что у пользователя 1С включена
  именно та аутентификация, которую использует Basic Auth (обычно "Аутентификация по протоколу
  HTTP" или "Аутентификация 1С:Предприятие" — зависит от версии платформы), и что в самом IIS
  не стоит анонимный доступ, конфликтующий с этим.
- **`$metadata` отдаёт пустой список / без нужных объектов** — техпользователю не хватает прав
  на конкретный справочник/регистр (шаг 4), или объект не отмечен в списке доступных при
  публикации (шаг 3a, если там был выбор объектов).
- **`Catalog_Номенклатура` возвращает 200, но без ожидаемых полей** (например нет артикула) —
  значит нужное поле — не стандартный реквизит, а доп.реквизит/доп.сведение; в стандартный
  OData такие поля обычно не попадают без явной настройки состава OData-объекта в конфигурации
  (это уже правка конфигурации 1С, не только публикации).
- **32-бит/64-бит IIS application pool** — если после публикации IIS отдаёт 500 при любом
  запросе, проверь, что application pool для этого сайта настроен под ту же разрядность, что и
  установленная платформа 1С (`Enable 32-Bit Applications` в Advanced Settings пула, если
  платформа 32-битная).
