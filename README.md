# ВИ-Портал

Корпоративный веб-портал для ООО ПО «ВОЛЖСКИЙ ИНСТРУМЕНТ»: публичный каталог,
электронные заказы, личный кабинет клиента, интеграция с 1С, публикация товаров
на маркетплейсах и управление складскими остатками.


## Структура проекта

```text
.
├── back/
│   ├── helper/
│   ├── integrations/
│   ├── migrations/
│   ├── orders/
│   ├── platforms/
│   ├── products/
│   ├── users/
│   └── warehouses/
├── front/
└── admin-front/
```

## Frontend

`front/` — Next.js (App Router, FSD, Effector, HeroUI). Публичная часть и
личный кабинет клиента. Админ-панель вынесена в отдельный проект
`admin-front/` на своём поддомене (`admin.wk.amctechgroup.ru`).

| Раздел | Маршруты |
| --- | --- |
| Публичные страницы | `/`, `/catalog`, `/product/:id`, `/brands`, `/about`, `/terms`, `/promo`, `/certificates`, `/contacts`, `/support`, `/assistant`, `/legal/:docId` |
| Кабинет клиента | `/cabinet`, `/cabinet/orders`, `/cabinet/orders/:id`, `/cabinet/documents`, `/cabinet/favorites`, `/cabinet/profile` |
| Оформление | `/cart`, `/checkout` |

`admin-front/` — отдельное Next.js-приложение (тот же стек: App Router, FSD,
Effector, HeroUI), деплоится и запускается независимо от `front/`.

| Раздел | Маршруты |
| --- | --- |
| Админ-панель | `/`, `/login`, `/content/:pageKey`, `/banners`, `/products`, `/products/:id`, `/categories`, `/legal`, `/users`, `/signup-requests`, `/feedback`, `/support`, `/audit-log` |

Доступ ко всем маршрутам `admin-front/`, кроме `/login`, проверяется в
`admin-front/src/proxy.ts` по cookie `admin_user_id` и подтверждается ролью
`admin` в `back/access`.

Модули без своего Go-сервиса (контент страниц, баннеры, юр. документы, заявки,
отзывы, обращения) обслуживаются route-handlers в `front/src/app/portal-api` —
единственный источник данных для обоих приложений (`admin-front` обращается к
ним через nginx-проксирование). См. README в этом каталоге и схему таблиц в
`docs/portal-content-schema.sql`.

### ИИ-помощник по подбору инструмента (M-04)

Работает на DeepSeek: модель через tool calling ищет позиции в `back/products`
и отвечает строго по найденному. Ключ задаётся переменной `DEEPSEEK_API_KEY`
(только на сервере, в клиентский бандл не попадает). Если ключ не задан или
модель недоступна — помощник автоматически работает на поиске по каталогу и
сценарных ответах, чат не ломается.

```bash
cp front/.env.example front/.env.local   # заполнить DEEPSEEK_API_KEY
```

Подробности и список переменных — `front/src/app/portal-api/README.md`.

## Backend-сервисы

| Папка | Модуль ТЗ | Назначение |
| --- | --- | --- |
| `back/products` | M-01 | Каталог продукции: товары, категории, характеристики, цены, поиск, прайс-листы. |
| `back/orders` | M-02 | Электронные заказы: корзина, оформление заказа, статусы, уведомления менеджеру и клиенту. |
| `back/integrations` | M-03 | Интеграция с 1С: синхронизация номенклатуры, цен, остатков, клиентов, заказов и счетов. |
| `back/helper` | M-04 | Интеллектуальный помощник: подбор инструмента по запросу клиента и связь с каталогом. |
| `back/users` | M-05 | Пользователи и личный кабинет: регистрация, роли, клиенты, индивидуальные условия, история заказов. |
| `back/platforms` | M-07 | Маркетплейсы: публикация и обновление товаров на Ozon, Wildberries и Яндекс Маркет. |
| `back/warehouses` | M-08 | Складские остатки: остатки по складам, пороги, блокировка заказа при отсутствии товара, уведомления. |
| `back/admin` | - | Админ-панель: вход сотрудников, журнал действий; отдельный backend для будущих разделов (контент, каталог, пользователи, отзывы). |
| `back/migrations` | - | Общие миграции базы данных. Это инфраструктурная папка, не отдельный микросервис. |

## Рекомендуемые недостающие сервисы

В ТЗ также есть модули, под которые пока нет отдельных папок:

| Рекомендуемая папка | Модуль ТЗ | Назначение |
| --- | --- | --- |
| `back/billing` | M-06 | Генерация счетов, накладных, УПД и PDF-документов по заказам. |
| `back/forecasting` | M-09 | Прогнозирование спроса, аналитика продаж и рекомендации по пополнению склада. |

Модуль M-09 в ТЗ отмечен как опциональный и включается в объем разработки после
подтверждения заказчиком.

## Планируемый стек

Согласно ТЗ backend может быть реализован на Python FastAPI или Go.

Рекомендуемые компоненты:

- PostgreSQL 14+ для основного хранилища.
- Redis и очередь задач для фоновых операций и интеграций.
- S3-совместимое хранилище для фотографий товаров и документов.
- OpenSearch, Elasticsearch или PostgreSQL FTS для поиска по каталогу.
- Docker Compose или Kubernetes для развертывания.
